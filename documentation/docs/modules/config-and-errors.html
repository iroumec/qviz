7  Configuration, constants and errors

This page documents two small modules that are used by every other module, and the exception hierarchy: backend/core/config.py, backend/core/constants.py and backend/core/errors.py.

The two constant modules

The values are split into two files, because they have two different meanings.

File Contents May be changed?
constants.py Mathematical and structural constants. No. They are part of the definition of the project.
config.py Policy parameters. Yes. They describe a choice, not a law.

Both are imported as modules.

from backend.core import config, constants

limit = config.MAX_QUBITS
turn = constants.TWO_PI

The fixed constants (constants.py)

Constant Value Meaning
TWO_PI 2 * pi One full turn, in radians. It is used for the turns-to-radians conversion.

These values never change. They are not configuration.

The tunable parameters (config.py)

Parameter Value Meaning
MAX_QUBITS 16 The hard cap on the circuit width.
MAX_STEPS_WARNING 500 If more steps than this are produced, a warning is logged.
VIBRATION_THRESHOLD 0.01 The smallest per-qubit error that is reported as vibration.
JSON_DECIMALS 6 The number of decimals used when a floating-point number is written.
REMOTE_JOB_TIMEOUT_S 60.0 The seconds to wait for the IonQ dry-run job. When the time is over, the local transpile is used.

How the width limit is used

The limit is not taken from MAX_QUBITS alone. The backend is also asked for its own number of qubits. The effective limit is the smaller of the two.

  • The cap is MAX_QUBITS, which is 16.
  • When the backend exposes a num_qubits attribute with a positive integer, the effective limit is min(MAX_QUBITS, backend.num_qubits).
  • When the backend does not expose it, the cap of 16 is used.

In this way, a circuit is never sent to a backend that is too small for it. For example, a 6-qubit circuit is rejected by a backend that has 5 qubits.

The check is made in transpiler._effective_max_qubits, at the start of the pipeline.

The cap is 16 for two reasons. First, the simulator keeps the whole statevector, which has 2^n complex numbers (a 28-qubit state alone takes 4 GiB), and every step goes through all of them; memory and time grow exponentially. Second, this is a visualizer: with more than about 16 Bloch spheres the picture is no longer readable.

The JSON schema follows the same cap: the maximum of total_qubits in documentation/schema/visualization.schema.json is 16, and a test checks that it equals MAX_QUBITS. If the cap is changed, the schema must be changed with it.

The error module

The file backend/core/errors.py defines a small hierarchy of exceptions. Only these exceptions are raised by the backend, so that a caller can catch all the expected failures with one except clause.

QVizError
├── UnsupportedOperationError
├── CircuitTooLargeError
└── TranspilationError
Exception Raised when
QVizError The base class, which is used to catch any QViz error. It is also raised directly for a wrong argument or a refused action: an unknown strategy, shots that is not positive, or tomography on hardware without allow_paid.
UnsupportedOperationError The circuit contains something that cannot be shown, for example a mid-circuit measurement, a reset, classical control flow, an unbound parameter, or a malformed entry in a native gate list.
CircuitTooLargeError The circuit is wider than the effective limit that is described above.
TranspilationError The circuit could not be transpiled for the chosen backend.

An unknown provider is not an error

If the provider of a backend cannot be recognised, no error is raised. The backend is handled by a generic strategy instead. This behaviour is described on the Provider page. An error is raised only when an operation has no meaning in a visualiser.
